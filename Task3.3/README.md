# Задание 3.3. API предстоящих записей

Спецификация: [openapi.yaml](openapi.yaml).

Фактический endpoint складывается из базового URL сервера и ресурса:

```text
GET /api/v1/appointments?status=upcoming&limit=20&offset=0
```

## Пагинация

Использована offset-пагинация с параметрами `limit` и `offset`, поскольку она прямо требуется условием и удобна для небольшого ограниченного списка предстоящих записей. `limit` ограничен диапазоном от 1 до 100, значение по умолчанию — 20; `offset` по умолчанию равен 0. Ответ содержит фактическое число элементов `count` и общее число подходящих записей `total`.

Для воспроизводимого результата записи сортируются по `startsAt` по возрастанию и затем по уникальному `id`. При частых изменениях большого списка offset-пагинация может пропустить или повторить элементы между запросами; в этом случае следующая версия API может добавить cursor-пагинацию, сохранив текущий контракт v1. Для предстоящих записей одного пациента объём невелик, поэтому усложнять MVP курсорами не требуется.

## Версионирование

Мажорная версия размещена в URL: `/api/v1`. Такой вариант явно виден мобильному клиенту, поддерживается правилами External API Gateway/WAF и позволяет параллельно обслуживать старые версии приложения. Обратимо совместимые изменения выполняются внутри v1: добавление необязательного поля, нового необязательного параметра или нового значения только там, где клиент обязан корректно обрабатывать неизвестные значения. Удаление/переименование поля, изменение его типа или семантики требует `/api/v2` и периода совместной поддержки версий.

## Аутентификация и ошибки

Метод требует Bearer JWT access token пациента, выданный CIAM по OAuth 2.1/OIDC. External API Gateway/WAF проверяет токен перед маршрутизацией запроса в BFF; API берёт идентификатор пациента из проверенных claims и не принимает `patientId` из query-параметров, чтобы исключить чтение чужих записей. Спецификация содержит требуемые ответы `200`, `401` и `500` с примерами; `requestId` в ошибке позволяет найти запрос в централизованных логах и трассировках.

В формулировке подзадачи упомянут OpenAPI 3.2, а в итоговых требованиях сдачи — OpenAPI 3.0. Файл подготовлен на **OpenAPI 3.0.3**, поскольку именно версия 3.0 указана в разделе «Как сдать работу» и широко поддерживается валидаторами и API Gateway.
